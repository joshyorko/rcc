## Question and scope

Measure five counterbalanced pairs of (a) current RCC Linux `artifactprovider.Filesystem.GetObject` for each of the 4,649 frozen small objects and (b) one indexed `os.File.ReadAt` over the retained concatenation of those same stored gzip frames. Each pass processes exactly 4,649 objects / 4,484,936 stored bytes in digest order. The sequence is filesystem, pack, pack, filesystem, filesystem, pack, pack, filesystem, filesystem, pack. Provider setup and source-copy validation happen outside timers.

This isolates current local object lookup and verification cost. It does not measure a network provider, Actions, materialization, acquisition, lifecycle, an RCC pack format, remote request coalescing, or an end-to-end gain. The pack arm uses a raw experimental file only; storage format, production source, existing provider, and defaults remain unchanged.

## Immutable inputs and untimed preflight

Inputs are the historical a709/stable3 provider Artifact `sha256:ec3795182e7261439a8b9a9a9b7bd0834b7a7d65202067b17e5589e06f41b83e`, index SHA256 `e587078b0b8d8bce38d4e665999b9a3a0d4d9fb1de1b87a8c3a4b223e71e50f6` (1,491,800 bytes), offset index SHA256 `e8dca8fa7d069883441bd8616e49234d338ab5707b3cc05d6b3a5693b2ba99e2` (525,841 bytes), and concatenation SHA256 `44d2341ac7cecf8a407e881bd4514e1f4fb6dd59530a4d172049d5c7e40f39a9` (4,484,936 bytes). Their source is `/workspace/work/rcc-swarm/evidence/performance-steer-20261011/runtime-prerequisites/attempt-10/attempt-10/provider-content`; read it only.

The harness pins the exact index/pack/offset hashes and rejects an unexpected subset. Before timing, it verifies all selected object files as regular files with exact size/SHA; creates a new, owned provider root in RAM and copies each object there; verifies offsets are nonoverlapping, digest-sorted, in bounds and cover exactly the pack; validates all pack slices; then calls `NewFilesystem` only on the new root. This preflight warms the same OS page cache for both arms; there is no eviction. It records source-closure digest over every selected file's contents, mode and mtime before and after the wave, plus index/offset/pack before-and-after SHA256. It never constructs a provider on the historical source root.

Untimed controls reject: corrupted provider bytes, a missing provider object, a wrong declared size, out-of-range and overflowing pack offsets, a wrong stored digest, and shared mutable state between pack result buffers/provider readers. Corrupted or missing objects are modified only in the owned RAM copy and restored before timing. Any failed control stops the run.

## Measurements and bounded execution

Each pass records monotonic wall nanoseconds, process user/system CPU delta from `getrusage`, object/byte totals, RCC `GetObject` calls or pack `ReadAt` calls, `/proc/self/io` `rchar`, physical `read_bytes`, and `syscr` deltas, plus a sampled `VmRSS` after the pass. Open/read reporting is explicit: filesystem reports 4,649 API calls, pack reports one pack file opened before timing and zero opens during a pass, 4,649 `ReadAt` calls; these are application-level counts. `syscr` is read-syscall count, not an open-syscall count. Do not describe it as syscall-level opens.

After each pass require 4,649 objects, 4,484,936 bytes and the same canonical digest/size result. Preserve all five raw pairs even if one fails. Per-pass and total timeout, workspace/RAM/free-space/RSS guards require an external supervisor; the Go harness alone does not kill a stalled pass. ## Interpretation

Report individual pass values and paired deltas/ranges, not just a median. The provider's internal secure directory traversal, `openat` and SHA verification remain part of its timing; pack does bounded range reads and the same SHA verification. This is a local component difference, not evidence that packing wins in Actions or over HTTP. A small result means defer a pack implementation; a large result would only justify a later versioned-format, corruption/repair, provider-semantics and hosted end-to-end proposal. No #125 direction, default change, or issue closure follows from this experiment.
