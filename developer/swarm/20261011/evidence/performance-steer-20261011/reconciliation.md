## Complete retained search and compatibility constraints

The [original completion clarification](https://github.com/joshyorko/rcc/issues/125#issuecomment-5387763459) compares six storage/materializer variants including the gzip control. The newest root admission additionally names prewarming/persistent workers as one of six research directions. Preserve both lists: gzip remains the control, all six directions below remain open, and process reuse is an operational axis evaluated against every materializer. OCI is a separate carrier/index question.

| Direction | Concrete falsifiable question | Minimum prerequisite / invariant |
| --- | --- | --- |
| zstd versus gzip | Does compression/decompression dominate a named phase, and does zstd improve complete consumer cost at acceptable stored bytes/CPU/RSS? | Repeated controlled current gzip baseline; exact stored-byte identity and dual-read/versioned-write plan; native/relocated file proof; rollback. |
| Small-object packfiles | Do object opens/stats/HTTP operations dominate enough that a hybrid pack reduces complete cost? | Current-only indexed object histogram/request count; separate relocatable/native objects; authenticated pack index, corruption/isolation/atomic publication and ordinary-object fallback. |
| Prewarming/persistent workers | Does a verified existing process avoid enough acquisition/startup/import work to beat a storage change? | Real reusable Action process, fixed source/environment identity, lease until reap; provider-call counter; reload/drain/cancel/resource bounds. Current real fixture disables reuse. |
| Safe reflinks/clonefile | Can supported filesystem COW reduce Drop and bytes written without cross-execution mutation? | Actual filesystem capability/runtime clone result; relocated-file exclusions, untrusted writable isolation, Python bytecode/native import and antivirus checks; ordinary Drop fallback. Hardlink safety is not inferred. |
| Lazy/virtual/FUSE | Can accessed-byte/metadata reduction repay mount/lookup/runtime cost for real consumer workloads? | Measured working set; actual mount/kernel/container permission; integrity before use, isolated writes, native libraries/relocation, cancellation/recovery/lease cleanup; eager fallback. FUSE is a mechanism, not the objective. |
| Immutable compressed filesystem image+COW | Can a cryptographically bound image plus per-execution writable overlay reduce startup/materialization while keeping the same portable lifecycle? | Native OS/filesystem mount support; immutable image/index identity and overlay authority; relocated/native/path behavior; per-execution mutation safety, generation drain/leases, crash/recovery/unmount, provider/offline rollback and eager fallback. |

Current [Manifest.IdentityBytes](https://github.com/joshyorko/rcc/blob/727c1ff8b679cdbbe12836e53c87734a1edb0071/environmentartifact/manifest.go#L132) includes catalog/index descriptors and requirements; [Validate](https://github.com/joshyorko/rcc/blob/727c1ff8b679cdbbe12836e53c87734a1edb0071/environmentartifact/manifest.go#L170) requires gzip/v12, and [ObjectIndex.Validate](https://github.com/joshyorko/rcc/blob/727c1ff8b679cdbbe12836e53c87734a1edb0071/environmentartifact/index.go#L63) requires gzip, stored digest/size, unique logical IDs and totals. Replacing gzip stored bytes while retaining their old cryptographic digest/Artifact identity is invalid. Two possible later experimental contracts are (a) physical local/provider packaging that still reconstructs the identical verified transport bytes and preserves the existing Artifact, or (b) explicit versioned new-format output with new stored/index/Manifest digests and old-reader/dual-read migration/rollback. Neither has been implemented or selected here. Preserving semantic inputs and exact old Artifact consumption must not be confused with retaining an old digest for changed identity-bearing bytes.
