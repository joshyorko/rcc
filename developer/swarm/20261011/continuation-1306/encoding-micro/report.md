## Frozen subject and method

`plan.json` was frozen before timing, SHA256 `0b335cdc43d1bfa3eff201e0f0690176f5d3f38d04319d190f33166d8b2a5e0d`. From each stored-size bucket, take eight evenly spaced sorted quantiles among objects with0<logicalSize<=1MiB, using the recorded deterministic Python rounding rule and no random seed. This excludes20 larger logical objects and one empty object. The sample contains1,478,176 original stored bytes and3,276,691 logical bytes. Eight samples per bucket overrepresent large objects relative to their count; aggregate results describe this selected corpus, not all5537 objects or an Action working set.

Every original stored object was SHA256/size checked, then gzip-decoded and checked against its exact `legacyObjectId` and logical size before timing. Logical payloads and all experimental frames stayed in memory. Codecs were already installed: CPython3.12.14, built-in zlib1.3.2, Pythonzstandard0.25.0/libzstd1.5.7. The frozen plan records Python and zstd extension hashes; the execution receipt records that zlib is built into the hashed Python executable. No dependency was installed.

External gzip uses level1/wbits31. External zstd uses level3, single-thread, content size and checksum, with a new codec context per object. Actual [Go LiftFile](https://github.com/joshyorko/rcc/blob/727c1ff8b679cdbbe12836e53c87734a1edb0071/htfs/functions.go#L223) uses `gzip.BestSpeed`. Equal numeric levels do not imply equal implementations: Python's level1 produced different bytes and sizes from actual Go gzip. Therefore the original stored gzip size and original-frame decode are actual fixture controls; the measured gzip encoding latency is an external zlib control, not a measurement of RCC's Go encoder.

Five repetitions alternate the two encode phases and three decode phases in the frozen order. Each timed batch performs20passes x24 objects, processing65,533,820 logical bytes through480 operations. The timer spans codec calls, fresh contexts, buffer allocation and output retention. It excludes original reads, preparation, hashes, roundtrip checks, reporting and the separate supervisor's resource observations. All480 outputs from every batch are checked after that timer, including exact logical SHA256/size and deterministic compressed-frame hashes for the encode batches. Buffer retention affects measured allocation cost; these are whole external codec batches, not pure algorithm CPU cycles.
