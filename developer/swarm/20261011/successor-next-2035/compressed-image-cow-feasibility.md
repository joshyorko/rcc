# RCC #125 compressed-image/COW source feasibility

**Disposition: no genuine source-only COW prototype is feasible on the inspected host/API boundary. No source or production files were edited; no build, benchmark, namespace, or mount operation was run.** This is scoped to the available host and frozen RCC source, not a universal rejection of compressed images or COW.

The frozen acquisition path verifies and stores manifest-referenced objects in the ordinary local Filesystem CAS, registers/rebases the portable catalog, and calls `Acquirer.materialize`. `NewAcquirer` hardwires `NewLocalMaterializer`; the `Acquirer` fields that could inject a provider/materializer are private. `LocalMaterializer.materializeLocked` opens the portable HTFS catalog, rebases it, restores into the ordinary Holotree target, verifies the materialized Python compatibility, and publishes a ready record. `ExecuteWithStreams` then uses a `Materializer` to create an execution lease and resolve a real executable/CWD from that ready materialization.

A custom `Materializer` can be passed to the public `Execute`/`ExecuteWithStreams` functions, but there is no public `NewAcquirer` injection point to run actual `Acquire → compressed image materializer → Execute` with it from another package. A package-internal test could inject one, but that does not provide the missing filesystem mechanism.

There is an existing *archive/transport* route: `environmentartifact.WriteArchive` creates a canonical ZIP carrier with ZIP `Store` members; the environment objects inside are already gzip-encoded. `environmentlifecycle.ImportArchive` validates manifest/index/descriptors and streams every member into the ordinary local CAS with rollback, after which the normal `NewAcquirer().Acquire` and `ExecuteWithStreams` lifecycle can run. Separately, legacy `htfs.ZipLibrary` opens ZIP members and gunzips them as `RestoreTo` relocates and writes regular materialized files. Both are eager archive/import or extraction paths. Neither exposes an image-backed COW filesystem, avoids the ordinary local CAS/HTFS restore, nor provides a mounted lower/upper layer. They could support a separately labeled archive-import/transport experiment, not a compressed-image/COW claim.

The actual storage contract adds further blockers. `Restore` performs consumer rebasing/relocation before files are executed; a mounted image must either encode consumer-safe paths or apply the existing relocation semantics without weakening validation. Image metadata and bytes would need a cryptographic index binding to artifact/manifest identity, bounded and canonical paths, no-symlink traversal, file type/mode/size checks, full-image and per-file logical hash verification. The mounted base must stay immutable; the writable layer must have isolated per-materialization ownership, crash reconciliation, lease-tied lifetime, and safe release/GC. Compatibility/Python probing must inspect the exposed composed tree. None of these controls can be honestly exercised by an archive-only substitute.

The retained host capability receipt says FUSE is registered but `/dev/fuse` is absent, so a FUSE mount cannot be tested here. It also records no `/dev/loop*` device and only the inspected loop-mount route as unavailable. The repository/container tool inspection found `bwrap`, but no SquashFS/EROFS userspace image tools; `bwrap` alone does not establish a usable overlay COW backend. The existing workspace overlay/EROFS lower mount is merely the host's enclosing filesystem and is not an isolated RCC materialization primitive. No `unshare`, mount, or namespace test was attempted.

The smallest genuinely useful next work is read-only attribution from the retained pack/compression CPU profiles, focusing on local CAS open/stat, importer validation, HTFS restore, and compatibility probes. The retained compression profile summary shows syscall-heavy worker time and `artifactprovider.openObjectDirectory` samples, which is a feasible target for source attribution without replaying completed measurements. Only after an actual mount/COW backend is already available should a separate package-internal harness exercise the complete lifecycle. Admission then requires: same artifact identity and closure; full index/image and logical file verification; path and symlink attacks rejected; relocation correctness; immutable lower and independent writable upper; 0700 owner/mode boundaries; compatibility probe on the mounted view; lease lifetime tied to mounted resources; crash reconciliation and no stale mount/upper after failure; exact output parity. Runtime measurement comes after those controls.

Relevant frozen source: `environmentlifecycle/materialize.go` (`Acquirer`, `NewAcquirer`, `LocalMaterializer.materializeLocked`, `Acquirer.materialize`); `environmentlifecycle/acquire.go` (verified-content/import path); `environmentlifecycle/execute.go` (`ExecuteWithStreams` and lease-bound execution). Retained capability facts are in `successor-1955/capability/report.md`; previous lifecycle and measurement status remains in the immutable successor report/restart. No measurements were repeated.
