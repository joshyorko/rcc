## Proposed guarded invocation

After separate root admission only, the runner will verify the manifest, all tracked/generated embed hashes, harness source, tool binary, index, offset index, source pack, and exact input sizes before build. It will make a disposable exact-7945 RAM source copy, install the reviewed harness as `prep-probe/main.go` with exclusive create, and copy the immutable pack into an owned runtime directory on `/dev/shm`. The harness checks that pack and provider destination are on the same tmpfs/device. The pack source and historical provider content remain read-only.

The runner builds with official Go and `GOTOOLCHAIN=local`, `GOENV=off`, `GOPROXY=off`, `GOSUMDB=off`, `GOTELEMETRY=off`, `CGO_ENABLED=0`, `GOOS=linux`, `GOARCH=amd64`, `-mod=readonly`. No download, shared-cache write, or Go module update is allowed. Runtime is one invocation, no retry.

Limits: 180 s combined build/runtime; 30 s build phase and 30 s per timed pass; 2 GiB sampled process-tree RSS; 1 GiB allocated owned RAM total including source, generated embeds, copied offline cache, temp, pack, provider, and result scratch; 32 MiB workspace allocation including binary, scripts, logs and receipts; workspace free-space floor 2,688,548,864 bytes. The current workspace has 135,500 bytes of preparation evidence. Before building, reserve the binary and all output budgets against the 32 MiB cap. Enforce a 30 MiB binary file limit, 1 MiB combined raw stdout/stderr cap, and bounded receipt size before every write. The runner records numeric build, harness, and outer exits without replacing failure with harness receipt status. It samples the process group and resources, joins both output readers, waits for process-group quiescence, and preserves partial receipts on failure.

Each pass's `PASS_START`/`PASS_DONE` stderr events enforce the per-pass deadline externally. The harness emits synced JSONL `run_start`, per-pass complete/failure, and final records so successful earlier passes survive a later error. Timed CPU includes Go verification/observer overhead; RSS is a post-pass sample, not a peak. The schedule is 3AB/2BA partial balancing, not full alternating balance. Report raw pass values and paired deltas without claiming a winner for Actions, remote HTTP, materialization, or production format.
