## One conditional next RCC-native experiment; currently **NOT ADMITTED**

**Question:** For a pinned representative native Action on the same qualified RCC and package, what fraction of materialized files is actually opened through first and five warm calls, and how much of cold acquire-to-first-Action wall is spent in provider transfer, verification, ordinary Drop, activation, Python startup/import and Action execution? A positive small touched-file count alone cannot rank FUSE/image because an opened mapped file may fault many or few pages, and mount/COW costs are unmeasured.

**Freeze before execution:** source-qualified RCC binary at one exact commit (proposed current `7945…`, with measured executable SHA), accepted Actions owner commit/binary and pinned native/heavy-library/relocation package/lock/wheels, a single provider Artifact+index digest, OS/CPU, cache class and execution settings. The Actions owner must first publish inspectable b614 successor and pass its cleanup/capacity controls; do not reuse/mutate its frozen historical homes. Match one ordinary eager source, Artifact and provider in both arms. Run at least five counterbalanced matched **untraced** controls and five **traced** observations, with exactly one consumer home active at a time and explicit cleanup between runs. Use `strace -ff` on the Action/Python process tree only to retain open/path/read and mapped-file evidence; map paths to immutable index digests. Keep RCC phase timers and provider byte/request counts separately. Calibrate tracer overhead against the untraced controls and do not use traced wall as a lazy speedup. For mmap, report opened/mapped files and aggregate faults as bounded proxies; without page-resolved accounting, actual touched page/byte fraction is **unknown**. This one study measures eager cost and a file-level working-set upper bound; it does not test FUSE or image speed.

**Proposed resource contract, not an allocation:** require free workspace **at least 3,762,290,688 B** before start (existing floor plus a **1 GiB** maximum incremental scratch reservation), cap newly owned provider/home/trace scratch at **1 GiB** with a hard abort before the floor, cap trace output at **128 MiB**, owned process-tree RSS at **2 GiB**, and the whole wave at **30 minutes**. These provisional caps must be checked against the owner's actual fixture size and natural cleanup before approval; a larger fixture means revise the admission, never borrow the floor or foreign homes. Preserve raw per-run exit, monotonic wall, child CPU, sampled/peak RSS with truthful `unknown` if unobservable, provider GET/body bytes, ordinary Drop file counts/bytes, open/map/read trace with path-to-digest mapping, host/mount/cache/process identity, source/binary/package hashes, and immutable per-arm input/output digests. Assert logical hash, modes/symlinks, native imports, relocation, Action outputs, leases and cleanup equal. Predeclare a useful end-to-end effect threshold before any later FUSE/image implementation/control. Publish raw failures and trace truncation, not only aggregate medians.
