# Representative maintained-repository workload design

## Selection

Use the frozen RCC `7945f956b428359928908a9f42e36417b113dafd` tracked-tree snapshot as the immutable input. Its `git archive` is 5,519,360 bytes, with 681 tracked paths and 4,927,749 logical file bytes. No `.git` directory is needed by these tests. The current `/workspace/rcc` checkout is a later commit; execution must consume only the coordinator's owned archive of the exact frozen commit, not that mutable checkout. The archive SHA-256 is `70654af0d400a8e04cbacaa72a7f3af65315a7a8f92f9f40d110c59c217cc204`.

Run two unmodified maintained developer CI suites through the materialized Python interpreter and the public RCC acquire/`ExecuteWithStreams` path:

- `scripts/test_validate_agent_docs.py`: all five unittest cases, followed by `validate_agent_docs.validate()` over the same full source snapshot. The tests cover valid-current-tree, bad link/skill, frontmatter/receipt errors, stable missing-file diagnostics, and a disappearing-file race.
- `scripts/test_validate_release_topology.py`: all 25 test cases from the frozen commit. These exercise the repository's release topology validator against current workflow/source files and synthetic local fixtures, including candidate identity, fail-closed policy, asset/index mapping, symlink rejection, and staged metadata. The suite invokes only local Python snippets and validator subprocesses; it does not publish, access a network, or run GitHub Actions.

The two selected suites use Python standard-library modules only. `robot_tests/environment_artifacts/task.py` is a less suitable alternate for this host: the installed Python 3.12.14 has PyYAML 6.0.3, but `_sqlite3` is builtin and has no `__file__`, which the task dereferences. Its repository conda file pins Python 3.11 and PyYAML 6.0.2, but this read-only design pass did not establish an available materialized artifact with those exact dependencies.

The existing `developer/benchmarks/test_lifecycle.py` was also checked but is not selected: it has seven unit tests, including an intentional 64,000,000-byte child allocation, and `source_sha()` shells out to `git rev-parse HEAD`. The exact frozen input is a `.git`-free archive, so using it would require adding Git metadata or altering the test's source lookup; both undermine this bounded exact-snapshot workload.

The six-work-item stream alternates `agentdocs`, `topology`, `agentdocs`, `topology`, `agentdocs`, `topology`: five tests plus one full guidance validation three times, and 25 tests three times, for 90 unit-test executions plus three additional whole-tree guidance validations per arm. A fresh arm uses one public `ExecuteWithStreams` call/child per task; the finite-resident arm sends the same six JSONL requests to one short-lived child. Both arms use the same artifact, provider, source snapshot, task ordering, and six-task input; cold acquisition is reported separately. This compares six request lifecycles in one child with six fresh child lifecycles. It does not claim an always-on daemon or OS security isolation.

## Driver and boundaries

`source/task_driver.py` is the source-only protocol driver. It accepts positional `mode INPUT_ROOT TASK_ROOT LEASE_DIR ARTIFACT START_SEQUENCE`, where `START_SEQUENCE` is an integer in `[1,6]`; control mode requires `1`. It reads JSONL requests on stdin and emits only compact JSONL protocol rows on stdout. Each worker validates that its first request matches `START_SEQUENCE`, then accepts only a strictly increasing sequence through 6 and enforces expected alternating job parity. The root worker should invoke it using RCC's ordinary `python` alias through the materialized artifact and `ExecuteWithStreams`; it should not emulate compatibility, bypass the importer, or inject runtime environment overrides.

The coordinator creates a private 0700 input root from the exact archive, strips `.git`, makes the source bytes read-only, computes the closure hash, and compares it before and after every arm. It creates a distinct owned 0700 task root per arm; the driver creates a 0700 `logs/` directory and a new 0700 `task-NN/tmp` per request. `TMPDIR` points into that request directory. Tests may create files/symlinks only there. The driver captures unittest output in a bounded per-task log, disables bytecode writes, and removes only its own task directory after each task.

Before each task, and after cleanup, the driver checks/restores process environment, cwd, argv, sys.path, tempfile's cached directory, bytecode-write setting, and modules imported from the source snapshot. Standard-library modules remain cached in the resident process. Each request loads a fresh unittest module/loader/suite from the original source file; it requires exactly 5 or 25 tests and records each test ID/outcome. It checks that exactly one active JSON lease exists before and after every task, that its embedded ID matches its filename, and that its artifact digest matches the requested artifact. Result rows include sequence, job, PID, lease IDs, test counts/outcomes, errors, source hashes, and clean-state proof. A real suite failure emits an ERROR row and stops the worker immediately.

This is trusted cooperative task isolation: it resets ordinary Python process state and provides private temporary directories. It is not a security sandbox against hostile code, an OS namespace, or a claim that separate tasks are safe to run concurrently. The source closure is read-only and input hashes detect any unexpected mutation.

## Untimed admission controls

Before timing, run the `control` mode with `poison-error` then `probe`. The poison control changes env/cwd/argv/sys.path/tempfile state and inserts a canary module rooted at the source tree, then raises the expected error; cleanup must emit status ERROR with `expectedError=true`, restore all state, and remove the canary. The next probe must PASS and prove clean state while the same lease remains active. The control process may continue after this expected error; measured worker mode may not.

Run cancellation separately with one request `cancel`. The driver starts a same-process-group Python sleep child, emits a flushed `cancel-ready` JSON row containing parent/child PIDs, `/proc` start ticks, process group, and active lease ID, then blocks. The Go writer cancels only after it parses that row. RCC's Linux supervisor kills the direct child on context cancellation; it does not itself kill a descendant process group. Therefore the bounded outer runner must own the process group, reap/terminate any remaining descendants, and verify the lease is absent after `ExecuteWithStreams` returns. If the controller cannot prove process-group cleanup, stop before the measured arms. This control is lifecycle evidence only, not an RCC sandbox claim. Frozen Unix `installLegacyImmutable` requests mode `0750` via `unix.Mkdirat`, but the admitted prototype runs with umask `0077`, and the controller observed the actual lease directory at `0700`; the driver strictly checks that observed `0700`. Private home/task directories also remain `0700`.

Use fresh `ROBOCORP_HOME` per arm, no pre-existing consumer CAS/materialization, exact artifact digest, full ordinary compatibility/import verification, and one acquire per arm before the six work items. Counterbalance fresh/resident arm order across three pairs. Require matching result rows for all six tasks, correct PID cardinality (six vs one), identical source closure hashes, no source writes, clean state and private task-temp cleanup, one lease while each request runs, strict lease cleanup after each fresh child/after the resident child, and final child census. Capture per-call and whole six-task wall times separately, CPU/resource/profile metrics with declared scope, and logs. These are exploratory results on a local warm-cache host, not a default winner or end-to-end RCC/Actions qualification.

## Evidence and limits

Read-only source evidence: exact commit `7945f956b428359928908a9f42e36417b113dafd`; archive size/count/hash above; frozen test counts are 5 and 25. The source driver passed an in-memory Python syntax parse only. No test suite, Go build, RCC acquisition, child workload, benchmark, network, or production modification was run in this design lane.
